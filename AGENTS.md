# Todoiste — Agent Instructions

## What This Is

A native macOS app that wraps Todoist's web app in a WKWebView and injects the
[todoist-shortcuts](https://github.com/mgsloan/todoist-shortcuts) Chrome extension
as plain JavaScript. The result is a standalone Mac app with full keyboard shortcuts.

## Commands

```bash
# Generate Xcode project (requires xcodegen)
xcodegen generate

# Build
xcodebuild -project Todoiste.xcodeproj -scheme Todoiste -configuration Debug build

# Run (after building)
open build/Debug/Todoiste.app  # or launch from Xcode

# Update vendored scripts from local fork (see Upstream Fork section)
cp ../todoist-shortcuts/src/mousetrap.js Todoiste/Resources/mousetrap.js
cp ../todoist-shortcuts/src/todoist-shortcuts.js Todoiste/Resources/todoist-shortcuts.js

# Update from upstream (after fork PRs are merged)
./scripts/update-shortcuts.sh
```

No build step or conversion is needed for JS files — source files are the distribution.
After updating vendored scripts, check upstream changelog for new options. If new
options are added, update `SettingsView.swift` and `injectOptions()` in `WebView.swift`.

## Architecture

SwiftUI app (`TodoisteApp.swift`) with a `WKWebView` wrapper (`WebView.swift`) that
loads `app.todoist.com` and injects four `WKUserScript`s at `.atDocumentEnd`:

1. **mousetrap.js** — keyboard binding library (vendored)
2. **Options script** (inline, generated by `injectOptions()`) — reads `UserDefaults`,
   sets `data-todoist-shortcuts-options` on `<body>` (replaces Chrome storage API)
3. **bootstrap.js** — hides "Configure options" link in help modal
4. **todoist-shortcuts.js** — the full shortcut suite (vendored)

Scripts execute in that order. All inject with `forMainFrameOnly: true`.

Native Settings (`SettingsView.swift`, ⌘,) exposes shortcut options. The extension's
settings link is intercepted and redirected to `todoiste://settings`.

### Key Design Decisions

- **Navigation policy** — todoist.com and OAuth providers stay in-app; external
  links open in default browser. OAuth popups load inline in main webview.
- **User agent** — set to Safari's UA so Todoist serves its full web app.
- **Persistent login** — `WKWebsiteDataStore.default()` persists cookies.
- **Notification bridge** — JS `Notification` calls shimmed and forwarded to Swift
  via `WKScriptMessageHandler`, then posted as native `UNUserNotificationCenter`
  notifications. Shim returns minimal object (`close()` only) — revisit if Todoist
  needs `onclick`/`addEventListener` on notification instances.
- **Options injection** — JSON embedded in JS string with manual escaping. Verify
  escaping if future option values include unusual characters.

## Code Conventions

- JS files in `Todoiste/Resources/` are vendored — do not hand-edit
- All script injection logic lives in `WebView.swift`
- Settings keys in `UserDefaults` must match option names expected by
  `todoist-shortcuts.js`

## Safety & Permissions

**Allowed:** Edit Swift source, update vendored JS from fork, modify project.yml,
update GitHub workflows.

**Ask first:** Changes to navigation policy or allowed domains, changes to
notification bridge behavior, modifying the options injection mechanism.

**Never:** Commit secrets or signing credentials, force-push to main, delete
vendored JS files without replacement, modify entitlements without understanding
sandbox implications.
