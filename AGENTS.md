# Todoiste — Agent Instructions

## What This Is

A native macOS app that wraps Todoist's web app in a WKWebView and injects the
[todoist-shortcuts](https://github.com/mgsloan/todoist-shortcuts) Chrome extension
as plain JavaScript. The result is a standalone Mac app with full keyboard shortcuts.

### How Script Injection Works

The Chrome extension uses `inject.js` to create `<script>` elements and
`common.js` to read/write `chrome.storage.sync`. We replace both with four
`WKUserScript`s injected at `.atDocumentEnd` via `WKUserContentController`:

1. **mousetrap.js** — keyboard binding library
2. **Options script** (inline, generated by `injectOptions()` in `WebView.swift`)
   — reads `UserDefaults` and sets `data-todoist-shortcuts-options` on `<body>`,
   which is how `todoist-shortcuts.js` reads its configuration (no Chrome APIs needed)
3. **bootstrap.js** — hides the "Configure options" link in the help modal (no
   extension options page exists; use Todoiste Settings instead)
4. **todoist-shortcuts.js** — the full shortcut suite

Scripts execute in order: mousetrap → options → bootstrap → todoist-shortcuts.

### Key Design Decisions

- **forMainFrameOnly: true** — scripts only inject into the main frame, not
  iframes. Todoist's app content is in the main frame.
- **Navigation policy** — todoist.com and OAuth providers (Google, Apple,
  Facebook) stay in-app. External links open in the default browser.
- **Popup handling** — OAuth popups are loaded inline in the main webview
  (WKUIDelegate's `createWebViewWith`).
- **User agent** — set to Safari's UA so Todoist serves its full web app.
- **Persistent login** — uses `WKWebsiteDataStore.default()` which persists
  cookies across launches.
- **Notification bridge** — web `Notification` calls are shimmed in JavaScript
  and forwarded to Swift via `WKScriptMessageHandler` (`todoisteNotifications`).
  Swift posts native notifications through `UNUserNotificationCenter`, and
  foreground banners are enabled via `UNUserNotificationCenterDelegate`.
- **Settings link interception** — the extension help modal's settings/options
  link is redirected to `todoiste://settings` and handled natively, so users
  configure options in Todoiste Settings instead of a Chrome extension page.
  Native Settings also provides an "Open Todoist Web Settings" action that
  navigates the main webview to `https://app.todoist.com/app/settings`.

### Maintenance Cautions

- **Notification shim object is intentionally minimal** — the wrapped
  `Notification` constructor returns a lightweight object (`close()` only),
  not a full browser `Notification` event target. If Todoist starts relying on
  `onclick`/`addEventListener` on notification instances, revisit the shim.
- **`injectOptions()` escaping is manual** — options JSON is embedded in a JS
  string with explicit escaping. If future option values include unusual
  characters, verify escaping remains valid.

The vendored `todoist-shortcuts.js` includes a fix for popover auto-close
([mgsloan/todoist-shortcuts#282](https://github.com/mgsloan/todoist-shortcuts/issues/282),
[#285](https://github.com/mgsloan/todoist-shortcuts/issues/285)) submitted as

PointerEvent dispatch (`pointerdown`/`pointerup`) to the `click()` helper, which
Todoist's UI (Radix UI) requires for popover toggle and outside-click dismissal.

The fork lives at `../todoist-shortcuts/` (sibling directory). Until the PR is
merged upstream, pull from the fork rather than upstream to keep the fix. The
GitHub Action's auto-PR is disabled for the same reason — see
`.github/workflows/check-upstream.yml`.

## Updating Vendored Scripts

The GitHub Action (`.github/workflows/check-upstream.yml`) checks for upstream
changes every Monday and opens a PR automatically (currently disabled — see
Upstream Fork section above).

To update manually:

```bash
# From upstream (after PR #290 is merged):
./scripts/update-shortcuts.sh

# From the local fork (before PR is merged):
cp ../todoist-shortcuts/src/mousetrap.js Todoiste/Resources/mousetrap.js
cp ../todoist-shortcuts/src/todoist-shortcuts.js Todoiste/Resources/todoist-shortcuts.js
```

No build step or conversion is needed — the source files are the distribution.
After updating, check the upstream changelog for any new options. If new options
are added, update `SettingsView.swift` with the new picker values and
`injectOptions()` in `WebView.swift` with the new keys.

## Known Limitations

- **OAuth popups** — handled by loading inline in the main webview. If a
  provider changes its OAuth flow, this may need adjustment.
- **Notification click-through context** — notifications currently open/focus
  the app, but do not deep-link back to a specific Todoist task yet.

## Debugging

- **Scripts not loading?** — Check Xcode console for `[Todoiste] Failed to load`
  messages. Ensure JS files are in the app bundle (Build Phases → Copy Bundle
  Resources).
- **Notifications not appearing?** — Verify macOS notification settings for
  Todoiste are enabled. Notification delivery is native (`UNUserNotificationCenter`)
  via the JS bridge in `WebView.swift`.
- **Shortcuts not working?** — Open Safari → Develop menu → select the app's
  webview to use Web Inspector. Check the console for errors from
  todoist-shortcuts.js.
- **Login issues?** — Check that the OAuth provider's domain is in the
  `allowedDomains` list in `WebView.swift`.
